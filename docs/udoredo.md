Реализация **Undo/Redo** (отмены и повтора действий) в профессиональном графическом редакторе — это не просто массив старых состояний. Если ты будешь сохранять весь тяжелый `AppState` целиком при каждом движении ползунка, память закончится через 5 минут.

Для **Dither Yuki** (Rust + Tauri + Zustand) лучшим подходом будет **Command Pattern** (Паттерн «Команда») с хранением только дельт (изменений).

Вот подробный план реализации:

---

# Архитектура Undo/Redo для Dither Yuki

## 1. Концепция: State Snapshots vs Commands
Мы будем использовать гибридный подход:
*   **Тяжелые данные (видео/картинки)**: Никогда не копируются. В истории хранится только ссылка на `asset_id`.
*   **Легкие данные (параметры эффектов)**: Хранятся как снимки (snapshots) или дельты.

## 2. Структура истории в Zustand
Вместо того чтобы вручную писать логику, рекомендую использовать middleware `zundo`, но с глубокой настройкой, чтобы не перегружать память.

```typescript
// src/store/useProjectStore.ts
import { create } from 'zustand';
import { undoMiddleware } from 'zundo';

export const useProjectStore = create(
  undoMiddleware(
    (set) => ({
      // Состояние проекта
      layers: [],
      activePalette: [],
      
      // Экшены для изменения
      updateLayer: (id, params) => set((state) => ({
        layers: state.layers.map(l => l.id === id ? { ...l, ...params } : l)
      })),
      
      // ... остальной стейт
    }),
    {
      // Ограничиваем глубину истории (например, 50 шагов)
      limit: 50, 
      // Исключаем тяжелые или временные поля (например, прогресс рендера)
      partialize: (state) => {
        const { renderProgress, isLoading, ...rest } = state;
        return rest;
      },
    }
  )
);
```

## 3. Группировка действий (Throttling)
Это критически важный момент. Если пользователь тянет ползунок «Контраст», он генерирует 60 изменений в секунду. Нам не нужно 60 шагов Undo.

**Как это реализовать:**
*   **Action Start**: Когда пользователь начинает тянуть ползунок (`onMouseDown`), мы фиксируем состояние.
*   **Action End**: Когда пользователь отпускает ползунок (`onMouseUp`), мы записываем одно финальное действие в историю.

## 4. Синхронизация с Rust (Backend)
Поскольку обработка идет на Rust, при каждом Undo/Redo фронтенд должен уведомлять бэкенд о смене состояния, чтобы тот пересчитал превью.

1.  Пользователь нажал `Cmd + Z`.
2.  Zustand откатил стейт.
3.  Срабатывает `useEffect` (или `subscribe` в Zustand), который вызывает `invoke('process_frame', current_state)`.

## 5. План реализации (.md для разработчика)

```markdown
# Реализация Undo/Redo System

## 1. Стек
- **Middleware**: `zundo` для управления историей в Zustand.
- **Интеграция**: Ссылка на хуки `undo()`, `redo()` и `clear()` в UI (верхнее меню или горячие клавиши).

## 2. Правила записи шагов (Commit Policy)
- **Мгновенные действия**: Переключение чекбокса, выбор палитры, удаление слоя — записываются в историю немедленно.
- **Непрерывные действия**: Изменение числовых значений (ползунки), перемещение слоев — записываются только по завершении жеста (событие `PointerUp` / `MouseUp`).

## 3. Оптимизация памяти
- В истории хранятся только сериализуемые данные (JSON-подобные структуры).
- Бинарные данные (Blobs, ImageData) исключаются из истории через `partialize`.

## 4. Горячие клавиши (Shortcuts)
Реализовать через глобальный слушатель событий в Tauri:
- `Cmd/Ctrl + Z` -> `undo()`
- `Cmd/Ctrl + Shift + Z` или `Cmd/Ctrl + Y` -> `redo()`

## 5. Сохранение истории в проект
- При сохранении в `.dyproj`, последние 20 шагов истории могут быть записаны в `manifest.json`, чтобы пользователь мог отменить действия даже после перезагрузки приложения (опционально).
```

## 6. Почему это важно для твоего формата `.dyproj`?
Когда у тебя есть четкая система Undo/Redo, ты можешь в любой момент "сбросить" проект до начального состояния. В манифесте проекта `project.json` поле `history` позволит художнику чувствовать себя в безопасности.
