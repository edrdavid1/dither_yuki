Мой план по внедрению работы с RGBA и CMYK 

Для начало нужно понять как мы сейчас работаем с цветом и как внедрять изменения что бы сразу правильно и с заделом на будущее так же понять как это затронет работу со слоями и сохранениями/открытием проекта 

Этап 1. Базовое разделение каналов RGBA 
Цель: дать пользователю возможность видеть и отключать отдельные каналы R, G, B, A.
Что сделать в бэкенде (Rust):
* Функция separate_channels(rgba: &[u8]) -> (Vec<u8>, Vec<u8>, Vec<u8>, Vec<u8>) (возвращает каналы как отдельные массивы байт).
* Функция combine_channels(r, g, b, a) -> Vec<u8>.
* Tauri-команды: get_channel_visibility, set_channel_visibility (хранить состояние каналов: boolean для R, G, B, A).
Что сделать во фронтенде:
* Панель с 4 иконками/переключателями (R, G, B, A).
* При переключении вызывать команду, пересчитывать превью: для каждого пикселя если канал отключён — ставить 0. Остальные каналы без изменений.
* Для альфа-канала: если отключён — выводить непрозрачность = 255 (полностью видимый, но исходный альфа не удаляется, просто игнорируется).


Этап 2. Инструменты для работы с каналами RGBA 
Цель: инверсия, коррекция яркости, копирование канала, использование канала как маски для эффекта.
Что сделать:
* Фронтенд: добавить на панель каналов кнопки: инвертировать канал, яркость (слайдер), копировать с другого канала.
* Бэкенд: функции:
    * invert_channel(data: &mut [u8], channel: u8) – где channel: 0=R,1=G,2=B,3=A.
    * scale_channel(data: &mut [u8], channel: u8, factor: f32).
    * copy_channel(src: &[u8], dst: &mut [u8], src_channel, dst_channel).
* Применить к выделенному кадру или ко всем кадрам анимации (опция).

Этап 3. Полноценный режим RGB Color с синхронизацией кадров 
Цель: чтобы настройки каналов сохранялись в проекте и не сбрасывались.
Что сделать:
* Добавить в структуру Frame поле channel_config: ChannelConfig (R=bool, G=bool, B=bool, A=bool, плюс параметры яркости/инверсии).
* При применении эффекта (дизеринг, глитч) → сначала «склеивать» каналы согласно конфигурации, потом применять эффект.
* При сохранении проекта сериализовать channel_config.


Этап 4. CMYK Halftone – базовый (только превью)
Цель: переключатель «Режим просмотра CMYK» без растра, просто цветовая симуляция.
Что сделать в бэкенде:
* Функция rgb_to_cmyk(r, g, b) -> (c, m, y, k) (по формулам, или крейт colorsys).
* Функция cmyk_to_rgb(c, m, y, k) -> (r, g, b).
* Tauri-команда get_preview_with_cmyk_simulation(rgba: &[u8]) -> Vec<u8>: для каждого пикселя конвертируем в CMYK, потом обратно в RGB – даёт «приглушённые» цвета, симулируя ограниченный охват.
* Хранить флаг view_mode: RGB | CMYK_Simulate.
Что сделать во фронтенде:
* Кнопка переключения режима просмотра (рядом с зумом, например).
* При переключении отправлять команду, получать новый буфер и обновлять canvas.
* Для анимации/видео – переключать режим только для текущего кадра, не пересчитывая все (по запросу).

Этап 5. Полноценный CMYK Halftone с растром 
Цель: настоящий печатный растр (точечная структура) с поворотом сетки.
Что сделать в бэкенде:
* Интегрировать крейт rotated-grid.
* Реализовать функцию apply_halftone(rgba: &[u8], width, height, angles: [f32;4], dot_size: u32) -> Vec<u8>:
    1. Конвертируем пиксели в CMYK (получаем 4 плоскости: C, M, Y, K).
    2. Для каждой плоскости генерируем растр: проходим по сетке, в каждой ячейке ставим точку, размер которой пропорционален интенсивности канала в этой ячейке.
    3. Все 4 растровых изображения складываем (альфа = 255) → получаем RGB для отображения.
* Добавить параметры: угол для каждого канала (например, C=15°, M=75°, Y=0°, K=45°), размер точки (линиатура), форма точки (круглая/квадратная).
Что сделать во фронтенде:
* Панель настроек Halftone (раскрывающаяся при активации режима просмотра CMYK).
* Слайдеры для углов и размера точки.
* Live-обновление превью при изменении параметров.

Этап 6. Экспорт в CMYK 
Цель: возможность сохранить изображение/кадры в форматах, поддерживающих CMYK (TIFF, PSD, JPEG с CMYK профилем).
Что сделать:
* Использовать крейт image с поддержкой CMYK? – в стандартной версии нет. Возможны варианты:
    * Сохранять как обычный RGB, но в метаданных указать, что это CMYK (грязно).
    * Использовать tex или psd крейты для генерации PSD с CMYK-каналами.
    * Экспортировать как 4 отдельных TIFF (C, M, Y, K) – неудобно, но честно.
* Реализовать Tauri-команду export_cmyk(path, data, options).
* Для видео – экспорт в RGB с опциональным наложением halftone эффекта (видео не поддерживает CMYK).
