# Спецификация формата проекта `.dyproj` (v1.0)

## 1. Концепция контейнера
Проект представляет собой **ZIP-архив без сжатия** (метод `Stored`), что обеспечивает мгновенный доступ к данным через смещения (offsets) без распаковки всего объема в RAM.

**Структура архива:**
- `manifest.json` — метаданные, дерево слоев, ссылки на ассеты.
- `timeline.bin` — бинарные данные кейфреймов и кривых анимации.
- `preview.png` — растеризованный текущий кадр для превью в ОС.
- `assets/` — локальное хранилище для встроенных (embedded) файлов.

---

## 2. Модель управления ассетами (Asset Management)
Каждый файл (видео или фото) обрабатывается согласно политике хранения.

### Типы хранения (`StorageMode`):
*   **Embedded**: Маленькие файлы (< 5-10 МБ) копируются в `assets/` внутри проекта.
*   **External**: Тяжелые видео остаются на диске, в проект пишется путь и хэш.
*   **Auto**: Система автоматически выбирает режим на основе размера и типа файла.

### Схема ассета в JSON:
```json
{
  "id": "uuid-v4",
  "type": "video | image",
  "storage": "embedded | external",
  "hash": "sha256:...", 
  "original_path": "absolute/path/to/file",
  "internal_path": "assets/filename.ext",
  "size_bytes": 102400
}
```

## 3. План реализации (Roadmap)

### Этап 1: Rust Backend (Tauri Commands)
1.  **Хэширование**: Реализовать быстрый расчет SHA-256. Для тяжелых видео (ГБ) считать хэш только по первым/последним 10 МБ + размер файла.
2.  **Бинарный движок**: Настроить `bincode` для записи таймлайна в `timeline.bin`. Это критично для плавной анимации с тысячами точек.
3.  **Custom Protocol**: Создать `tauri::protocol`, который позволит видеоплееру стримить файлы напрямую из архива или по внешним путям, обходя ограничения безопасности браузера.

### Этап 2: Логика "Relink" (Поиск потерянных файлов)
При загрузке проекта реализовать каскадный поиск:
1.  Проверка `internal_path` (внутри архива).
2.  Проверка `original_path` (абсолютный путь).
3.  Поиск в папке рядом с файлом проекта `.dyproj`.
4.  Поиск по хэшу в системной базе кэша.
5.  Если файл не найден — статус **Media Offline** и вызов диалога выбора файла.

### Этап 3: Frontend (React & Zustand)
1.  **Project Snapshot**: Создать селектор, который собирает весь `AppState` в структуру проекта.
2.  **Dirty State**: Реализовать отслеживание изменений (если текущий стейт != сохраненному, показывать `*` в заголовке).
3.  **Auto-save**: Фоновый процесс, сохраняющий `manifest.json` и `timeline.bin` в папку `AppData/Local/DitherYuki/Autosave` каждые 5 минут.

---

## 4. Алгоритм сохранения (Save Workflow)

1.  **Collect**: Сбор всех параметров эффектов, палитр и путей к файлам с фронтенда.
2.  **Process Assets**: 
    - Для новых файлов вычисляется хэш.
    - Если файл маленький, он помечается как `embedded` и Rust копирует его в папку `assets/` внутри проекта.
3.  **Write Binary**: Сериализация анимационных треков в бинарный формат.
4.  **Zip It**: Упаковка всех компонентов в `.dyproj` без сжатия.

---

## 5. Почему это "Pro" уровень?
*   **Скорость**: Бинарные данные загружаются в десятки раз быстрее JSON.
*   **Надежность**: Благодаря хэшированию, перемещение папок с исходниками больше не "ломает" проект окончательно.
*   **Автономность**: Маленькие проекты (коллажи, фото) — это один файл, который можно переслать другу, и он откроется мгновенно со всеми картинками.

- **Rust**: `zip`, `bincode`, `serde_json`, `sha2`, `walkdir`.
- **JS**: `zustand`, `uuid`.
