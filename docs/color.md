Для реализации этих функций нам нужно изменить логику инициализации проекта и расширить пайплайн обработки цвета в Rust. Это сделает работу с цветом более предсказуемой и даст гибкость, как в профессиональных графических редакторах.

Вот детальный план реализации:

---

## 1. Автоматическая экстракция при импорте
Чтобы при добавлении видео/фото оно не превращалось в дефолтное «ЧБ», мы меняем порядок действий в `Index.tsx` и `commands.rs`.

*   **Workflow:** Как только файл выбран, фронтенд вызывает команду `extract_palette`.
*   **Инициализация:** Полученная палитра сразу записывается в стейт слоя. Теперь первый просмотр кадра уже идет в цвете, извлеченном из оригинала.
*   **Default State:** Если экстракция невозможна, используется стандартная палитра (например, `CGA` или `GameBoy`), но никогда не «пустой» стейт.

## 2. Система «Master Palette» и пресетов
Чтобы можно было всегда вернуться к исходным цветам, мы вводим в структуру проекта понятие **Initial State**.

*   **Snapshot:** При первом импорте ассета в `project.json` (в секцию `assets`) записывается массив `initial_palette`.
*   **UI-кнопка:** В `ColorStudioDialog` добавляется кнопка **"Reset to Source"**. Она берет данные из `initial_palette` и перезаписывает текущую рабочую палитру.
*   **Global Presets:** Проект хранит ссылку на `base_preset_id`. Это позволяет переключаться между "авто-цветом" и, например, пресетом "Retro PC" без потери исходных данных кадра.



---

## 3. Управление каналами (RGB Toggle)
Это реализуется на уровне Rust-движка (`image_engine`), так как обработка пикселей происходит там.

### Логика в Rust:
В структуру настроек кадра/слоя добавляем флаги каналов:
```rust
struct ColorChannels {
    r: bool,
    g: bool,
    b: bool,
}
```
При обработке каждого пикселя в `quantize` или `dither`, если канал выключен, его значение принудительно зануляется перед квантованием или во время финальной сборки кадра.

### Экспорт:
Поскольку флаги каналов являются частью `ProjectSettings`, команда рендера видео (`process_video_frames`) просто учитывает эти коэффициенты. Если канал `G` выключен в UI, он будет выключен и в финальном `.mp4`.

## 4. Обновленный план для разработчика (.md)

```markdown
# Работа с цветом и каналами (Phase Color+)

## 1. Auto-Color Onboarding
- При импорте ассета вызывать `extract_palette` ДО первого рендера превью.
- Записывать результат в `current_palette` и `initial_palette` (для бэкапа).

## 2. Каналы (RGB Killswitch)
- Добавить в UI (Color Studio) три чекбокса: R, G, B.
- Передавать эти булевы значения в Rust-команды `process_frame` и `process_video`.
- В Rust-движке реализовать маскирование каналов:
  `pixel.r = if channels.r { pixel.r } else { 0 };`

## 3. Persistent Color State
- В `manifest.json` хранить массив `palette_history`, чтобы пользователь мог переключаться между результатами разных экстракций.
- Реализовать функцию `restore_source_palette()`, которая берет цвета из метаданных ассета.

## 4. Экспорт
- Убедиться, что состояние каналов учитывается при финальной сборке кадра в FFmpeg пайплайне.
```

## Почему это важно:
1.  **Первое впечатление:** Пользователь сразу видит красивый дизеринг в цветах своего видео, а не «сломанную» ЧБ картинку.
2.  **Эксперименты:** Возможность выключать каналы (например, оставить только красный) — это мощный инструмент для создания стилизованного ретро-арта (эффект старых мониторов или спецэффектов).
3.  **Безопасность:** «Первоначальный пресет» дает художнику право на ошибку при ручном редактировании палитры.

Это дополнение отлично вписывается в наш формат `.dyproj`, так как все эти настройки (флаги каналов, бэкап палитры) — это просто дополнительные поля в `manifest.json`.
